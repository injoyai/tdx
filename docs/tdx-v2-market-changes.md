# tdx v2 市场接口改造实施说明

**首要交付目标：在现有报文和业务操作范围内，以后修改某个市场的行为，生产代码只改该市场的接口实现。** 例如，香港基金的分钟量规则由 `hk.go` 中的基金路由决定。改这条规则应能直接作用于 SDK 查询和 pull 落库；港股股票、港股指数、美股各自按自己的实现运行。测试应能证明这项隔离。

所有市场由 SDK 维护者逐个写进源码。此次允许修改公共层，是为了把分散在调用方的市场判断迁回接口边界。后续增加同类市场时，按同一约定增加一个市场实现即可。全新的报文布局需要在协议层实现一次解码；新增公共业务操作属于单独的接口契约变更。

**实施基线**：[github.com/injoyai/tdx，分支 codex/dev-v2，提交 87ba0d3](https://github.com/injoyai/tdx/tree/87ba0d3d5be804219219fcc2d3fa5e71cb462194)。本文所有源码路径均相对该仓库根目录。当前交付物是实施任务书；下列预期结果是修改后的验收条件。

## 1. 开工与范围

1. 在目标仓库读取 `AGENTS.md`、`PROJECT_RULES.md`、`MEMORY.md`、`docs/unified-client.md` 和 `docs/public-contracts.md`。运行下面的命令核对实际版本。若分支已有后续提交，对照文中的函数名复核现象，保留已合入的修复。
2. 先做 T0 的规则归属和现有市场对照，再按 T1–T6 迁移调用链。每项先补离线用例，再改实现并复测。把保持现有行为的迁移和有意修正结果的变更分开验证。T2 的路由定义供 T3、T4 使用；T5 的无损换算供 T6 使用。
3. **接入方式固定为源码内置。** 沿用各市场文件的 `init()` 和包内私有 `registerMarket`。生产改动围绕已有市场，用测试市场验证下一个市场的接入成本。外部市场注册 API、运行时加载、全量补齐市场和批量创建占位实现均在任务范围之外。现有 `pull.Register(Unit)` 只涉及拉取任务。SQLite 文件路径和已有市场 ID 属于持久化契约。

## 2. 市场定义与调用方的职责

| 归属 | 由此处声明 | 通用代码如何使用 |
|---|---|---|
| `Market.Info()` / `RouteInfo` | 逻辑简称、稳定市场 ID、协议编号、连接协议、代码来源、批量报价格式、收盘调度 | 注册表做索引，Client 选连接，pull 选适配器；同一逻辑市场可有多个协议编号 |
| `Market.Resolve()` 与可选的裸码匹配规则 | 代码语法、规范化、可识别的裸码、共享代码的候选路由与快照归属 | 公共解析器处理输入形式和冲突，得到同一个 `Instrument`；进入分页后保留已确定的协议编号 |
| `Market.Rules(Instrument)` | 品种类别、各操作支持情况、可用字段、各周期单位换算、竞价及补线规则 | 连接按规则解释原始槽位，pull 接收统一业务值，存储按原值写入 |
| 协议及公共设施 | 已知报文布局、分页、重试、压缩与文件读取、SQLite 事务和路径编码 | 同一种布局实现一次；由市场定义选择具体布局、文件成员和解释规则 |

沿用 `Info / Resolve / Rules`。只有部分市场需要的新行为优先做成可选能力或数据字段。现有导出接口的调用者也要纳入兼容性检查，包括外部实现的 `tdx.Client`。归属导入可以在注册表内部按能力调用；若要从已导出的 `Market` 接口移除 `Import`，须另行处理通过接口调用该方法的现有代码，本期可保留兼容入口。

### 单市场变更应落在哪里

| 以后要改的行为 | 唯一决定该差异的位置 | 自此往下如何复用 |
|---|---|---|
| 上海某类代码的归属、分类 | `protocol/market/sh.go` 的匹配和品种规则 | 公共解析器只执行匹配顺序，分类、发现、查询共用解析结果；裸码冲突按已有优先级处理 |
| 香港基金的分钟量规则 | `protocol/market/hk.go`，限定到协议编号 49、分钟操作 | K 线换算读取该操作的倍率；pull 与 SQLite 直接消费统一量。日线、报价及同属香港的 31、27 各取自己的规则 |
| 期货类指数是否提供分笔价格 | `protocol/market/qhz.go` 的分笔规则 | Client 读取 `Trade.Fields.Price` 和相应换算规则；中金所合约按 `cff.go` 的规则处理 |
| 北交所代码报表成员或已支持的读取方式 | `protocol/market/bj.go` 的来源描述 | 连接按描述下载和解析文件；分页、计数及元数据同步复用同一结果 |

**共享实现的边界**：共用代码可以包含分页算法、布局解码器、单位换算函数，以及返回独立规则值的构造函数。市场主动选用这些实现并传入自己的参数。以 `equityRules` 为例，香港和美国都复用它；香港基金独有的变化在 `hk.go` 取得规则值后按路由和操作覆盖。可变字段、布局选择和能力开关均须能从该市场实现独立决定。必要的行为差异可由市场提供回调，公共层统一调用。一次请求解析出证券后，把已选路由和操作规则传到实际消费处，尤其是响应解码和补线环节。公共调用方不再按市场简称、编号、代码前缀或共享协议猜业务含义。

### 市场只实现一部分时的行为

| 调用方的问题 | 实施依据与预期行为 |
|---|---|
| 行情服务器列出了哪些市场？ | `Client.GetMarkets()` 沿用市场发现契约，扩展服务器列出的编号可以出现在结果中，即使 SDK 还没有实现它。 |
| 当前 SDK 内置了哪些路由？ | 以源码构建出的 `protocol.Markets()` 和 `Exchange.Route()` 为准。pull 的内置适配器从这里枚举。协议常量、服务器市场表和证券归属快照均不能自行创建路由。 |
| 该路由能处理这项查询吗？ | 先查内置路由，再查证券对应的操作、周期和字段规则。缺少路由时，统一业务入口返回“市场尚未接入”；有路由但操作未实现时，返回该操作不受支持。已确认支持的操作可单独交付。 |

以现有的 `ExchangeNQ`（44，新三板）为例，原始协议能识别该编号。验收本次改造只需验证它的发现与未接入行为；无需实现新三板行情。后续正式接入该市场时，将未接入用例换成另一个尚无路由的编号。

## 3. 实施任务

### T0　先固定现有市场边界

以本次会动到的规则为单位，追踪「市场实现 → 共享构造函数 → 解码/查询 → pull/存储」，找出同一决策被作出两次的位置。优先核对三组已有耦合：`sh.go / sz.go / bj.go` 调用 `standardSecurityInfo`，`hk.go / us.go` 调用 `equityRules`，`cff.go / qhz.go` 调用 `futuresRules`。复用算法是允许的；如果一个市场必须更改共享默认值才能表达自己的差异，就在这次迁移中给市场实现补上该选择，并把调用方旧判断移除。

先用相同输入固定目标市场、同市场其他路由，以及共享同一构造函数的其他市场的公开结果。只比较本次涉及的字段和操作。已确认缺陷的目标用例使用 T1–T6 的正确预期，其余样本取自已有契约和固定报文。每迁出一项规则即跑该组测试，优先复用 `protocol/market/market_test.go`、`volume_test.go` 和 pull 的现有样例。

### T1　修复代码语法优先级和协议编号越界

**入口**：`protocol/market/instrument.go` 的 `ParseInstrument`，`code.go` 的 `decodeCode / splitPrefix`，`exchange.go` 的 `ParseExchange`；下游包括 `extend/pull/code.go` 和 `extend/httpserver/query.go`。

**基线**：`WIX.US` 被解释为市场 12 的 `X.US`；`USB.US` 被解释为市场 74 的 `B.US`。`600000.257` 与 `600000.-255` 都因 uint8 回绕而进入上海。

**改法**：先识别显式前缀和完整市场键，再识别显式后缀；显式前缀后的点属于代码主体。只有未选定市场时才尝试无分隔前缀和裸码推断。全数字或带符号的数字市场后缀按市场编号语法校验，超出 8 位无符号范围立即报错。范围合法与是否已接入统一 Client 分开校验，保留原始协议按编号访问的能力。将市场相关号段和裸码匹配放回相应市场定义，保留最长前缀和既有歧义优先级；pull 仅额外处理自己注册的 Unit。

**验收**：`WIX.US`、`us.WIX` 和裸 `WIX` 均得到 `(74, WIX)`；`USB.US` 得到 `(74, USB)`；`us.BRK.B` 和 `BRK.B.US` 的主体均为 `BRK.B`。同时覆盖 `000001` 默认深圳、`SHOP`、`HKL`、`hk/fund.02800`、`02800.hk/fund`、`cff/IF2609`。SDK、pull 和 HTTP 对适用输入一致；非法编号在业务调用发包前失败。

### T2　统一协议选择，校验批量报价布局

**入口**：`protocol/instrument_snapshot.go: QuoteProtocol`、`conn_query.go: protocolInstrument`、`client.go / conn_ex.go: GetQuoteList`、`protocol/model_ex.go: DecodeQuoteList`、`extend/httpserver/handler_ex.go: handleExQuoteList`。

**改法**：已解析证券以注册的 `RouteInfo.Protocol` 选连接。兼容保留的 `InstrumentRules.Protocol` 从路由派生或显式校验一致。需要快照的代码从候选路由取得协议；只有候选协议一致才能在归属确定前选连接。保留港股显式编号、已导入归属、快照唯一匹配及未知代码报价探测的原有行为。

在路由上声明经过验证的批量报价格式。保留 `GetQuoteList(market, category, start, count)` 的签名，用路由校验调用方传入的类别；未知、未支持或不匹配的组合在发包前返回错误。底层解码区分“不支持的布局”和“合法的零条记录”。HTTP 使用相同校验。新增隐式推断入口如有需要，可用独立函数，避免给所有 `Client` 实现新增必选方法。

**验收**：复用一份市场 31、含一条记录的模拟报文。类别 2 正确读出买盘；类别 3、9 返回错误，模拟连接写入数为零。合法类别的空页正常返回。保留已有期货类别 3 测试。共享代码候选在同一协议下能选连接，跨协议歧义返回可诊断错误。

### T3　让分类与元数据校验消费注册表

**入口**：`protocol/market/code.go` 的 `IsStock / IsETF / IsIndex`、各市场的 `Rules`、`extend/model/codes.go` 的 `StandardCode / ValidateCodes`、`extend/model/snapshots.go` 的 `CodeSnapshot.Validate / GbbqSnapshot.Validate`、`extend/pull/metadata.go: FetchCodes`。

**改法**：在便捷函数公开支持的品种范围内，先解析证券再按分类判断。保持标准板块可按指数识别及 ETF/LOF 现有范围，避免把所有基金一概视为 ETF。核对 `us.AAPL` 当前为 `SecurityOther` 的原因；只有可验证的品种信息才可用来细分，同一路由内证据不足的品种保留 `Other`。

标准市场由 `ex.Route()` 返回的 `ProtocolStandard` 判定。快照按注册的规范简称和解析后的代码主体比对，去掉 `ex <= ExchangeBJ` 与固定两个字符的切片。继续拒绝重复记录、超出快照范围的记录和不支持的扩展市场元数据。股本数据如另有能力限制，用该业务契约单独表达。

**验收**：`IsIndex("sh.000001")`、`IsIndex("sh000001")` 对同一指数返回相同值。三字符标准市场能通过代码快照校验，默认 `FetchCodes()` 包含该市场；已注册扩展市场仍不能混入标准代码快照。保留原有非法行、重复行和空范围验证。

### T4　将代码发现来源移入市场定义

**入口**：`protocol/market/bj.go`、`conn_st.go: getStandardCodeAll / GetCount / GetCode`、`extend/pull/market/standard.go` 与 `block.go`。

**改法**：标准列表分页、扩展全局名录过滤、压缩报表下载各复用现有实现。对于报表来源，让市场选择文件成员和解析方法。把北交所使用 `FileTdxBjMore` 与 `ParseTdxBjMore` 的对应关系放到其市场定义可选择的策略中；保持 Go 包依赖单向，避免 `protocol/market` 反向导入 `protocol`。可以在低层声明来源标识，在拥有解码器的层绑定已有函数。板块补录使用已确定的目标路由生成规范代码，避免重新猜测归属。

**兼容与验收**：`GetIndexCodeAll()` 仍按公开契约返回沪深指数并包含 `bj899050`，`GetStockCodeAll()`、`GetETFCodeAll()` 保持已声明范围。用包含两个成员的本地压缩包验证不同来源可以复用下载流程、各取各自的文件；成员缺失返回包含市场与文件名的错误。未知来源不得默认为普通分页。

### T5　修复 K 线成交量的提前截断与二次换算

**入口**：`protocol/model_kline.go` 的标准 K 线解码、`protocol/market/rules.go: StandardKlineVolume`、`conn_st.go: GetKline`、`query.go: GetKlineMinute241Until`、`volume.go`。

**基线**：上海股票模拟分钟报文的量槽为 150，先整除 100 再乘 100，统一接口得到 100。另一个测试市场的分钟倍率设为 10，同一条 09:32 数据经普通分钟入口返回 10，经 241 入口返回 100。

**改法**：在解码边界保存计算业务量所需的原始数量。普通行情直接按证券、周期规则得到最小单位；中途转换为整数手会丢余数。保留 `Standard.Volume` 和 `StandardResponse()` 既有单位契约，必要时在内部同时携带无损输入。241 入口保留普通分钟结果，仅重算真正拆分的竞价及首分钟，先将分笔量和分钟量转到同一单位再做加减。按字段可用性保留缺失值，并沿用负量与溢出检查。

**验收**：上述股票模拟报文在统一结果中得到 150 股，旧原始响应语义可单测验证。对 09:32 行，普通与 241 入口的 OHLC、量、额一致。对有竞价的首分钟，拆分前后总量及总额守恒。覆盖股票、ETF、转债、标准指数、板块；保留指数日内量不可用、金额未知为 `nil` 的契约。

### T6　交易时段、竞价和分笔补线分别声明

**入口**：`protocol/model_history_minute.go`、`protocol/model_kline.go: FixKlineTime`、`query.go: GetKlineMinute241Until`、`extend/pull/market/standard.go` 与 `fallback.go`。

**改法**：区分三种时间用途。调度使用 `MarketInfo.TimeZone / CloseTime`；报文带时间时保留其来源语义；只有需要从序号推导分钟钟面的布局才使用交易时段规则。让已解析的市场规则随请求到达需要它的解码位置。沪深时段仍可共用一份定义。分别表达“支持拆竞价”和“允许用分笔补分钟”，补线使用对应品种的分笔数量、金额规则。仅在确认适用的市场和布局启用午休时间修正。

**验收**：沪深 09:30 竞价、午休、收盘样例与原契约一致。使用一份无午休的模拟时段，第 121 条按连续交易时钟生成；报文本身已有时间的扩展行情保持来源时间。只开启竞价能力时，pull 不应发起分笔补线请求。对固定 241 格式表达不了的时段，原有 241 专用入口明确返回不支持，普通分钟入口仍可用。

## 4. 跨包验收与交付

**现有市场隔离验收（首要验收）**：用测试专用 Go overlay 对完成改造后的 `hk.go` 做一次局部替换，只把市场 49 的分钟成交量倍率从 100 调为 10；同一份测试程序和报文分别运行正常构建与替换构建。在两次运行间，唯一变化的生产源文件应是这一个市场实现。以下检查通过后丢弃替换，生产定义保留已核实的真实倍率。

| 对照输入 | 预期结果 |
|---|---|
| 香港基金 `02800.49`，解码后的分钟数量槽为 2 | 普通一分钟查询的统一量从 200 变为 20；用相同报文走 pull，SQLite 回读量也从 200 变为 20。金额和价格逐字段相等 |
| 同一基金、同样数量槽的日线 | 两次均为 200，证明修改只作用于分钟规则 |
| 香港股票 `00700.31`、美股 `us.AAPL`，同样数量槽的分钟线 | 香港股票两次均为 200，美股两次均为 2。分别验证同文件相邻路由与跨市场共用构造函数的隔离 |
| 港股指数 `hk.HSI` 的分钟线 | 两次的成交量都为 0，成交额按指数规则换算，证明数量槽的含义也按品种隔离 |

若这一处修改仍需同步编辑 `rules.go` 的公共算法、`conn_ex.go`、pull 或 SQLite，说明该规则仍在接口之外，先修正调用链再验收。新增市场测试另验注册和发现，不能代替上述现有市场的局部修改测试。
